## 基础层

### 运行时基础类型与基础设施

`include/aethermind/base/` + `src/base/`。

- **职责**：基础宏与断言、错误模型、对象所有权、设备、张量元数据、环境变量与 workspace 类型。
- **关键结构**：`Status` / `StatusOr<T>`（与 `am_status_code` 通过 `static_assert` 一一对应）；intrusive 引用计数 `Object` / `ObjectPtr` / `WeakObjectPtr`，空句柄用每类型 `EmptyObjectSentinel` 而非裸 `nullptr`；`Device`（CPU/CUDA/CANN）、`Tensor` / `TensorView`、`ShapeAndStride`、`Scalar`、`mmap_file`、`KernelSelector`。
- **约定**：运行时主路径返回 `Status`；构造函数与不变式违反用 `AM_CHECK`；编译器与 sanitizer 差异集中在 `macros.h` 的 `AM_*` 宏。

### 通用工具库

`include/aethermind/utils/`。

- **职责**：跨层共享的哈希、安全整数运算、浮点解析、断言日志、variant 访问与限定名。
- **关键结构**：`CheckOverflowAdd/Mul/Sub`、`CheckNarrow`、`SafeMultiplyU64`；`aethermind::hash<T>`（优先 `T::hash`，再枚举底层值，最后 `std::hash`）；`ParseFloat` / `ParseDouble`（Apple 回退 `strtod_l`，其余 `std::from_chars`）；`AM_CHECK` / `AM_DCHECK`；`overloaded`；`QualifiedName`。
- **约定**：算术与转换 API 采用 `(in, out) -> bool overflowed`；公开 API `noexcept`；平台相关实现放 `detail::`。

### 容器与字符串基础库

`include/container/` + `src/container/`。

- **职责**：非拥有数组视图、SSO 字符串 `AMStringCore`、引用计数 `String`、迭代器与数字工具。
- **关键结构**：`array_view.h` 在 `std::span` 与自定义 `ArrayView` 间切换；`AMStringCore` 用 `MagicConstants` 做大小端位布局压缩；`StringImpl` 继承 `Object`、`String` 通过 `ObjectRef` 共享；`details::IteratorAdapter` 支持 KMP / Boyer-Moore / Naive 查找。
- **约定**：C++20 与旧标准双实现通过 `CPP20` 宏；热路径用 `AM_UNLIKELY` 配合 `memcpy` / `memmove`；断言统一 `AM_CHECK` / `AM_DCHECK`。

### amstring 字符串库

`include/amstring/`（独立头文件库，与 `container/amstring.h` 的 `AMStringCore` 是两套实现）。

- **职责**：提供带 SSO、可配置布局与增长策略的 `BasicString`。
- **关键结构**：`BasicStringCore` 负责构造析构、拷贝移动与分配协调；`LayoutPolicy` concept（`GenericLayoutPolicy` 使用 24 字节 Small/External union，`CharLayoutPolicy` 对 `char` 做紧凑布局）；`GrowthPolicy` 常量集中在 `aethermind::config`；`AllocatorTraitsHelper` 处理 `propagate_on_*_assignment` 与 `is_always_equal`。
- **约定**：API → Core → Policy 单向转发；策略在编译期由 `AmStringLayoutPolicy` / `AmStringDecodedLayoutPolicy` concept 校验。

### 张量元素数据类型与数值类型定义

`include/aethermind/dtypes/`。

- **职责**：DLPack 兼容类型编码、Half/BFloat16/Float8、复数与跨类型转换。
- **关键结构**：`DLDataType` / `DataType`（code/bits/lanes 校验、字节大小、自然对齐、vscale）；`half`、`bfloat16`、`float8_e4m3fn`、`float8_e5m2`；`complex<T>`；`cast.h` 的 `is_cast_overflow` / `check_and_cast`；`detail/floating_point_bits.h` 共享位级操作。
- **约定**：低精度类型提供 `from_bits_t` + `from_bits()` 与 `bits()`，区分语义转换与位直通；算术先转 `float` / `double` 再窄化；bfloat16 的 `is_iec559` 为 false。

### 形状推断与约束求解核心

`include/aethermind/shape_inference/`。

- **职责**：符号维度、广播、形状约束、计划期求解与绑定期重放。
- **关键结构**：`ShapeSymbol`（负数为符号、-1 为 Unknown）与 `SymbolicShape`（`Join` 合并控制流、`Unify` 严格对齐算子输入）；`TensorSpec`；`ShapeConstraint` sum type（DimEqual / DimBroadcastable / VolumeEqual / RankEqual / RankAtLeast / DimPositive）；`InferBroadcastShape` 产出 `DeferredBroadcastAxis`；`SymbolConstraintSolver` 用并查集维护等价类；`EvaluateShapeConstraint` 返回 `{kSatisfied, kViolated, kDeferred}`；`ValidateTensorBindingPremises` 在绑定阶段重放前提。
- **约定**：符号身份由原子计数器保证互异；对外 API 标注 `AM_NODISCARD` 并返回 `StatusOr`。

### 设备无关内存分配与缓冲层

`include/aethermind/memory/`。

- **职责**：跨设备分配抽象、分配器注册表、共享所有权 Buffer 与可转移 MemoryHandle。
- **关键结构**：`MemoryHandle`（device + alignment + 可选 `memory_deleter_fn`，空 deleter 表示借用）；`BufferImpl` / `Buffer`；`Allocator::TryAllocate` 把 `AllocateStorage` 的失败统一规约为 `Status`；`AllocatorRegistry` 按 `DeviceType` 注册 Provider 并缓存实例；`cpu_allocator` / `cuda_allocator` / `cann_allocator`；`memory_junk_fill`。
- **约定**：`BufferImpl` 构造用 `AM_CHECK` 校验设备类型、2 的幂对齐与 CPU 指针对齐；OOM 映射为 `ResourceExhausted`；`AllocatorRegistry` 不加锁，要求调用方串行化。

### C ABI 与 Any/Format 基础设施

`include/c_api.h` + `src/c_api_*.cpp`、`src/any.cpp`、`src/format.cpp`。

- **职责**：C 运行时/模型/会话 API、跨边界错误诊断、`Any` 值类型与 Tensor 格式化。
- **关键结构**：零拷贝句柄 `am_runtime_t` / `am_model_t` / `am_session_t` / `am_error_handle`；`am_config_t` / `am_session_config_t` 以 `struct_size` + `abi_version` 自检；`AMErrorObject`（`am_status_code` + message）；`aethermind::Any` 小对象内联/大对象堆分配；`std::format` 风格 Tensor 打印。
- **约定**：C 函数不抛异常，错误经 `am_status_code` 与可选 `am_error_handle*` 输出；`*_create` / `*_destroy` 成对，NULL 销毁为 no-op。

### 构建、基准与验证工具集

`tools/`。

- **职责**：基准运行、参考数据生成、验证与维护脚本。
- **主要脚本**：`run_model_benchmark.py` + `verify_model_benchmark.py`（契约与可复现性证明）；`generate_llama_numerical_reference.py` + `verify_llama_numerical_reference.py`；`generate_fp32_admission_hf_fixtures.py`；`calibrate_*` / `prepare_*` 参考数据工具；`verify_cpu_isa_build.py`、`verify_ctest_report.py`、`check_docs_links.py`；`run_add_op_tests.sh`、`run_broadcast_tests.sh`、`run_final_validation.py`。
- **约定**：脚本用 `Path(__file__).resolve().parents[1]` 定位仓库根；版本字典硬编码并在运行时校验；`verify_*` 与 `run_*` / `generate_*` 成对出现。

## 模型管线

### Hugging Face 模型格式读取

`include/aethermind/model/formats/hf/` + `src/model/formats/hf/`。

- **职责**：目录探测、config/index JSON 解析、safetensors 零拷贝读取、张量名解析与三阶段校验。
- **关键结构**：`HfSafetensorsFile` 基于 mmap 返回共享 `RawStorage` 上的 `RawWeightView`；`HfSafetensorsIndex` 解析分片索引；`hf_directory_reader` 的 `InspectDirectory` 区分单文件/分片并暴露 `ParseConfig` / `LoadRawWeightTable`；`HfJsonReader` 为零拷贝顺序解析器（`kMaxSkipDepth=32`）；`HfModelConfig` 与 config.json 字段 1:1；`hf_tensor_resolver` 处理 tied embedding；`hf_model_validator` 执行 `ValidateConfig` → `ValidateWeightSet` → `ValidateResolvedModel`。
- **约定**：失败返回 `StatusOr<T>`；读取前用 `RejectExistingPathIfSymlink` 拒绝符号链接；I/O 对象采用私有构造 + `Open`/`Load` 静态工厂与 Rule of 0。

### 模型权重管理与打包

`include/aethermind/model/weight/`。

- **职责**：原始权重存储统计、FP32 宽化、逻辑绑定解析与按后端 recipe 预打包。
- **关键结构**：`WeightPackingRequest` 承载每个权重视图的 OpType、source_id、value_index、binding、selector 与 recipe；`PackedWeightCollection` 以 `WeightArtifactKey`（五元组）管理 `shared_ptr<const PackedWeight>`，`PrepackWeightRequests` 批量调用 `Backend::PackWeights` 并保证全部成功或全部回滚；`ResolveWeightBinding` 是 Qkv/GateUp 复合绑定与 tied lm_head 回退的唯一决策点；`raw_weight_storage_usage.h` 提供 owner-aware 去重的 `RawWeightStorageUsage`；`raw_weight_fp32_conversion.h` 以 `RawWeightFp32ConversionOptions`（scope、转换回调、`max_owned_weight_bytes`）执行 F16/BF16→FP32。
- **约定**：所有权通过 `shared_ptr<const PackedWeight>` 与 `ExecutionPlan` 共享；可选上限用零值表示不限；标识用多字段结构体而非单一 key。

### 模型加载与语义图构建

`include/aethermind/model/` 顶层头文件。

- **职责**：把 HF 目录装配为后端无关的 `LoadedModel`，再生成语义 `ModelGraph`。
- **关键结构**：`ModelLoader::Load` 是唯一入口；`LoadedModel` 持有 `HfModelConfig` + `ResolvedModelWeights`；`build_model_graph.h` 通过 `ParseModelArchitecture` 分发到 `llama_dense_graph_builder`，`transformer_graph_common` 与 `rope_params_builder` 提供共享的 Transformer 参数构造。
- **约定**：图构建属于 model 模块，`graph` 只拥有 IR、rewrite framework 与 semantic passes；loader → formats → validator → graph builder 单向依赖，图构建不反向引用 loader。

## 图与算子

### 计算图 IR 与优化 Pass 框架

`include/aethermind/graph/` + `src/graph/`。

- **职责**：DAG IR、增量重写会话与顺序执行的优化 Pass 管线。
- **关键结构**：`ModelGraph` 由 `GraphNode` / `GraphValue` / `GraphInput` / `GraphOutput` 组成，`AddNode` 加入前调用 `InferOperator` 做形状与 schema 校验；`GraphRewriteSession` 提供 `RemoveNode` / `RedirectInput` / `ReplaceValue` / `SubgraphReplacement` 四类原子改写，`Commit()` 物化并剪枝；`GraphPass` 只暴露 `Name()` 与 `Run(GraphRewriteSession&, const PassContext&)`，`GraphPassManager` 按序调度并支持每 N 步 checkpoint。
- **常量折叠**：`ConstEvaluator` 采用 `Plan`（可行性、布局、保守 `FoldingCost`）/ `Evaluate`（写字节）两阶段，预算由 `CheckFoldingBudget` 统一执行；evaluator 覆盖 add/mul/silu/silu_mul/cast；`FindConstEvaluator(OpType)` 静态分发。
- **内置 Pass**：常量折叠、死代码消除（`IsDceRemovableOp`）、QKV Linear 融合、GateUp+Linear 融合、SiLU×Mul 融合、Add+RMSNorm 融合。
- **约定**：Pass 无状态且 `const noexcept`，禁止直接访问 `ModelGraph`；可配置性通过 `PassContext` 的 `enable_*` 标志早返回。

### 算子定义与推理层

`include/aethermind/operators/` + `src/operators/`。

- **职责**：统一的算子身份、参数、Schema、形状/类型推断与序列化，作为后端与图构建之间的稳定契约。
- **关键结构**：`OpType` 枚举 + `ToString` / `std::hash` 特化；`OpParams` 强类型结构体，RoPE 用 `RoPEAlgorithmParams = std::variant<Standard, Linear, DynamicNtk, Yarn, Llama3, LongRoPE>` 表达算法族；`OperatorSchema` 用 `OperatorInputPort` / `OperatorOutputPort` / `OperatorTraits` / `StateAliasPortPair` 描述端口、角色、副作用与可编译期求值属性；`InferOperator` 与 `aethermind::detail` 下的 `InferXxx` 返回 `InferenceResult`（输出 shape/dtype + `runtime_checks`）；`op_params_serde` 提供稳定文本格式；`rope_frequency_resolver` 统一频率表构造。
- **约定**：新增 `OpType` 时必须同步 `ToString`、Schema 静态表与 `InferOperator` 分发；`StateAliasPortPair` 是 lowering 生成状态别名记录的唯一来源；推断失败返回 `Status` 而非抛异常。

## 编译、执行与运行时

### 模型编译器与图降阶

`include/aethermind/compiler/` + `src/compiler/`。

- **职责**：`ModelCompiler` 串联构图、语义优化与后端无关的图降阶，产出不可变 `LoweredGraph` 并派生权重打包请求。
- **关键结构**：`ModelCompiler::LoadAndCompile` / `Compile` 依次调用 `BuildModelGraph`、`OptimizeModelGraph`、`LowerModelGraph`；`LoweredGraph` 由 `LoweredStepSpec`、`LoweredStepBinding`、`LoweredStep`、`LoweredStateAlias`、`LoweredValueDesc` 组成，只允许嵌套 `Builder` 写入并在 `Build()` 后冻结；`weight_packing_request_builder` 从 `LoweredGraph` + `ResolvedModelWeights` 映射出 `WeightPackingRequest`。
- **约定**：编译器工件类型与执行期类型保持分离；lowering 通过 `KernelSelector` 选目标，不持有 Backend 或 `KernelRegistry`。

### 执行计划与内核调度层

`include/aethermind/execution/` + `src/execution/`。

- **职责**：为编译产物提供冷路径绑定、运行时上下文、按序步骤调度与冻结内核调用。
- **关键结构**：`ExecutionPlan`（已验证的 `ExecutionStep` 序列 + 逻辑值表 + `StateAliasPlan`）；绑定分两步——`PlanExecutionBindings` 计算激活区布局，`PrepareExecutionBindings` 分配存储并构建 `StepTensorBinding` 与 `kernel_params`，结果由 `PreparedExecutionBindings` 以 heap-stable storage 持有；`ExecutionContext` 聚合绑定、`WorkspaceArena*` 与 `KVCacheSessionView`；`Executor::Execute` 是唯一公开调度入口，内部 `LayerRunner::Run` 顺序遍历并校验状态别名；`InvokePreparedKernel` 消费已准备参数。
- **约定**：依赖单向 `executor → layer_runner → kernel_invoker → backend`；绑定与计划之间用 `ExecutionPlanBindingKey` / `IsCompatible` 做冷路径校验；热路径不持有编译器或图 IR 句柄。

### 运行时装配与工作区规划

`include/aethermind/runtime/` + `src/runtime/`。

- **职责**：Runtime 生命周期、后端/分配器/KV 装配与执行期 workspace 布局规划。
- **关键结构**：`RuntimeOptions` 聚合 allocator/backend/execution/workspace/tracing/kv_cache 六个子结构；`RuntimeBuilder` 维护待注入 Provider/Factory 列表，依次构建 `AllocatorRegistry`、`BackendRegistry`、`KVCacheManager`，`Build()` 走 abort 路径、`TryBuild()` 走 `StatusOr` 可恢复路径；`Runtime` 私有构造、仅 `RuntimeBuilder` 可创建并按设备懒创建后端与分配器；`WorkspaceRequirement` / `WorkspaceBinding` / `WorkspacePlanLayout` 由 `PlanWorkspaceRequirements` 一次性计算偏移与对齐。
- **约定**：失败后保留已注册 Provider/Factory 以支持重试；长期资源懒初始化并内部缓存；workspace 规划阶段不做堆分配。

### 推理会话与可执行模型

`include/aethermind/inference/` + `src/inference/`。

- **职责**：从编译器工件构建不可变 `ExecutableModel`，并通过 `InferenceSession` 执行同步 Prefill + Decode。
- **关键结构**：`ExecutableModel::Prepare` 持有 `ExecutionPlan`、`ExternalTensorBindings`、打包权重与 artifact；`InferenceSession::Create` / `Generate` 编排单请求生成；`WeightPolicy` / `ModelLoadOptions` / `GenerationConfig` 表达权重与 KV 策略；`ModelResourceUsage` / `RequestResourceUsage` 输出资源报告；私有辅助集中在 `inference_internal.h`。
- **约定**：`ExecutableModel` 与 `InferenceSession` 借用 `Runtime`，`Runtime` 必须地址稳定且生命周期更长；成员按声明逆序销毁（先 plan/bindings，再元数据、权重、artifact）；类为 move-only。

### KV Cache 物理布局与会话管理

`include/aethermind/kv_cache/` + `src/kv_cache/`。

- **职责**：连续 KV 平面布局、单会话生命周期与跨计划追加/读取的可见性。
- **关键结构**：`KVCacheLayout` 以 `num_layers × num_kv_heads × max_tokens × head_dim` 组织 key/value 平面，`PlanKVCacheLayout` 零分配计算带对齐 padding 的 stride；`KVCacheStorage` 持有 layout 与两个 `Buffer`；`KVCacheSessionState` 用 `Lifecycle`（Idle / AwaitingPrefill / PrefillCommitted）+ `generation` 追踪；`KVCacheManager` 同一时刻只允许一个活动会话，经 `ReserveForSession` / `ResetSession` / `ReleaseSession` 控制；`KVCacheSessionView` 以 `generation` 失效检测，`BindLayerForAppend` / `BindLayerForRead` 产出绑定，`CommitAppend` 推进提交水位。
- **约定**：索引与步长计算统一走 `*Validated` 辅助并返回 `StatusOr`；`KVCacheManager` 需调用方串行化；视图只借用不拥有缓冲。

## 后端与内核

### 后端抽象与内核注册中心

`include/aethermind/backend/` + `src/backend/`。

- **职责**：设备后端、内核与打包权重的统一接口，以及进程级注册与候选查询。
- **关键结构**：`Backend` 定义 `PrepareKernel` / `PackWeights` 等能力，`BackendFactory::Create` 返回 `StatusOr<unique_ptr<Backend>>`；`BackendRegistry` 维护 `DeviceType → BackendFactory` 并懒加载缓存；`KernelRegistry` 以 `RegistrationKey`（OpType + `KernelSelector` + `CpuFeatureSet`）去重、按 OpType 建桶，`Freeze()` 后禁止注册；`AM_REGISTER_KERNEL` 在文件作用域完成静态注册；`KernelSelector` / `ResolvedKernel` / `PackedWeight` / `PackingRecipe` 是跨层契约。
- **约定**：外部只通过 `BackendRegistry::GetBackend` 与 `KernelRegistry::Global()` 访问；`SetFactory` 同时失效同设备缓存；形状/字节计算统一做溢出检查。

### CPU 后端与打包权重运行时

`include/aethermind/backend/cpu/` + `src/backend/cpu/`。

- **职责**：CPU 设备实现——能力检测、内核筛选、权重打包与工作区。
- **关键结构**：`CpuBackend` / `CpuBackendFactory` 继承通用接口，按 `CpuCapabilities` 快照过滤候选并冻结 `ResolvedKernel`；`CpuFeatureSet` / `CpuFeaturePolicy` / `cpu_info` 提供无分配能力描述与探测；`cpu_packed_weight_layout` 定义 `kCpuIdentityPackingLayout` 与 `kCpuBPanelF32Kc512Nr16Layout`，`packed_weight_validation` 提供 `PlanIdentityWeights` / `PlanBPanelF32Kc512Nr16Weights` 与溢出校验；`CpuWorkspaceArena` 对连续内存做线性绑定与 Reset。
- **约定**：布局 ID 不可变，格式变化必须新增 ID；`PackWeightsWithRecipe` 是注册表之外的打包原语；SIMD 实现按 ISA 后缀命名并由 selector 选择。

### CPU 参考内核

`src/backend/cpu/kernels/<op>/`。

- **组织方式**：每个算子目录遵循三件套——`*_entry.cpp` 构建参数并注册，`*_internal.h` 声明 POD 参数与 `Run*` 入口，`*_f32_reference.cpp` 提供纯标量实现；SIMD 特化（如 `gemm_f32_avx2`、`rmsnorm_f32_avx2`）按 ISA 后缀分离。
- **GEMM / MatMul**：`GemmF32Args` / `PackedGemmF32Args`，reference / scalar / AVX2-FMA 三级回退，packed-B 变体固定 KC=512、NR=16；`CpuMatMulF32Reference` 注册到 `OpType::kMatMul`。
- **线性算子**：`Linear`、`QKV-Linear`、`Gate-Up Linear` 共用 `AnalyzeRowwiseView` + `ValidateRowwiseOutputLayout` + `ValidateRowwiseDisjoint`，可选 `Run*F32PackedB`。
- **逐元素**：`Add` 支持 F32/F64/BF16/I32/I64 广播，`SiLU` 与 `RMSNorm` 支持精确 in-place 或互斥 footprint 校验，RMSNorm 另有 AVX2/FMA 与 packed weight identity 路径。
- **RoPE / ArgMax / Embedding**：`rope` 以 POD 头 + 逆频率表写入 attrs 并支持六种算法；`argmax` 冻结 axis；`embedding` 提供 packed identity 变体。
- **Attention / KVCacheUpdate**：缓存指针由 `KernelContext::kv_read` / `kv_append` 注入，布局安全统一由 `alias_utils.h` 的 `BuildStridedAddressFootprint` / `ValidateLayoutInjectivity` / `ValidateStridedDisjoint` / `ByteRangesOverlap` 证明。

### CPU 推理 CLI 应用

`apps/inference/`。

- **职责**：`aethermind_infer` 可执行程序，加载 HF 模型并执行 CPU 推理。
- **关键结构**：`inference_main.cpp` 用 `FlagSpec` 表解析 `--model`、`--tokens`、`--context-tokens`、`--max-new-tokens`、`--eos-token-id`、`--preset`；`inference_runner` 暴露同步 `RunInference`，用 `RunStage` 定位失败阶段，`ValidateRunOptions` 校验输入与 `HfModelConfig` 兼容性。
- **约定**：数值解析用 `std::from_chars` 并拒绝空串/溢出；`std::bad_alloc` 转为 `ResourceExhausted`；构建开关 `BUILD_INFERENCE_TOOL`，默认 OFF。

## 顶层工程

### 构建系统

`CMakeLists.txt` + `cmake/` + `CMakePresets.json`。

- 强制 CMake ≥ 3.28、C++20 与 `<format>` 可用，否则 `FATAL_ERROR`；全局 PIC。
- 子目录：`src`、`apps/inference`（`BUILD_INFERENCE_TOOL`）、`tests/unit`（`BUILD_TESTS`）、`tests/benchmark`（`BUILD_BENCHMARKS`）。
- `cmake/` 提供依赖获取、CPU ISA 探测、Sanitizer 注入、libbacktrace、构建检查、Python 发现与测试标签。
- `AETHERMIND_SANITIZER=none|asan-ubsan|tsan` 经 C/C++ 双向 compile+link 探针后仅注入 project-owned target。
- Preset 分为 validation、benchmark、CLI-only 三类，各自固定 `binaryDir`、targets 与 JUnit 输出。

### 配置系统

无外部配置文件，采用三层 C++ 配置模型。

- **编译期**：`CompilePreset`（`kO1Plain` → opt_level=1、无 packed weight；`kO2Packed` → opt_level=2、启用 packed weight）。
- **装配期**：`CpuRuntimeAssemblyOptions`（context_tokens、kv_max_bytes、workspace_limit_bytes、cpu_feature_policy、kv_dtype）经 `MakeCpuRuntimeOptions` 映射为完整 `RuntimeOptions`。
- **运行时**：`RuntimeBuilder::WithOptions` → `TryBuild` 校验选项、注册表、KV 布局与字节上限。
- **环境变量**：`base/env.h` 的 `get_env` / `set_env` / `check_env`，模块初始化时注入 `THP_MEM_ALLOC_ENABLE=1` 与 `TRACEBACK_LIMIT=512`。
- 未实现的 `execution.*` / `workspace.*` / `tracing.*` 选项返回 `Unimplemented`；零字节上限表示不限。

### 依赖管理

CMake 是唯一入口，不使用语言级包管理器。

- spdlog v1.17.0、googletest v1.18.0、google-benchmark v1.9.5 经 `aethermind_declare_shared_dependency` + `AcquireSharedDependency.cmake` 拉取到 `.deps/`。
- libbacktrace、cpufp、STREAM 以 `3rdparty/` 子模块提供。
- 获取流程：参数校验 → 进程级 `file(LOCK)` → 校验独立仓库、tag SHA、无本地修改 → staging clone → 原子 rename；离线时进入 VERIFY 模式。
- Provider 必须提供完整 target 集（如 `GTest::gtest` + `GTest::gtest_main`），否则 `FATAL_ERROR`。

### 错误处理

两套机制按边界分工。

- **异常**：`Error` + `AM_THROW` / `AM_THROW_SILENT` + `ErrorBuilder` + `TRACEBACK_HERE`，用于内部不可恢复的编程错误。
- **返回值**：`StatusCode` / `Status` / `StatusOr<T>` + `AM_RETURN_IF_ERROR`，是运行时主路径的错误模型。
- **C ABI**：`am_status_code` 与 `StatusCode` 逐值 `static_assert` 对齐；`am_error_*` 对象封装错误码与消息，全部不抛异常。
- **Traceback**：libbacktrace + demangle，`TRACEBACK_LIMIT` 控制深度，Python 边界与 gtest 帧自动排除。

### 日志系统

spdlog 是唯一日志后端。

- CLI 在 `main` 首项创建 `stderr_logger_mt("aethermind_infer")` 并设为默认 logger；库与 C ABI 不替换宿主 logger。
- 源码中实际只有 `cpu_allocator.cpp` 一处 `spdlog::warn`，无结构化字段、sink 切换或级别管理。
- logger 初始化失败与 OOM 分支用 `std::fputs` 直接写 stderr，避免二次分配；模型基准在运行前 `set_level(off)` 保证 JSON 纯净。
