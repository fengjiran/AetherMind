模块按职责分为三层：
- 几何与布局层（kv_cache_layout.h/.cpp）：`KVCacheLayout` 以 `num_layers × num_kv_heads × max_tokens × head_dim` 的连续平面组织 key/value，并通过 `PlanKVCacheLayout` 在零分配前提下计算带对齐 padding 的 stride；所有索引偏移走 `OffsetValidated`/`BytesPerPlaneValidated` 等受检路径。
- 状态与所有权层（detail/kv_cache_state.h + kv_cache_manager.h/.cpp）：`KVCacheStorage` 持有 layout 与两个 `Buffer`，`KVCacheSessionState` 用 `Lifecycle`（Idle / AwaitingPrefill / PrefillCommitted）+ `generation` 追踪单会话；`KVCacheManager` 同一时刻只允许一个活动 session，通过 `ReserveForSession` / `ResetSession` / `ReleaseSession` 控制其生命周期，且必须被调用方串行化。
- 借用视图层（kv_cache_session_view.h/.cpp）：`KVCacheSessionView` 仅借指 manager 拥有的 storage 与 session state，通过捕获 `generation` 实现失效检测；通过 `BindLayerForAppend` / `BindLayerForRead` 产出 `KVCacheAppendBinding` / `KVCacheReadBinding`，由上层 plan 事务在全部层写入完成后经 `CommitAppend` 推进全局提交水位。
依赖方向单向：manager → layout + detail/state；session view 仅反向借指针，不拥有任何缓冲。CPU 侧要求平面基址满足 layout.alignment，以保证内核观察到绝对对齐的 token 行。
