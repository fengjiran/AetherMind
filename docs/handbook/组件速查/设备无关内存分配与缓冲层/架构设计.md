模块以三层结构组织：
- 核心句柄层（memory_handle.h）：`MemoryHandle` 是移动独占的原始指针包装器，携带 device、alignment 和可选的 `memory_deleter_fn` 销毁回调；空 deleter 或 `NoOpMemoryDeleter` 表示借用内存。
- 缓冲层（buffer.h）：`BufferImpl` 持有可见字节数与 `MemoryHandle`，在构造时通过 `AM_CHECK` 校验设备类型（kCPU/kCUDA/kCANN）、对齐为 2 的幂、CPU 指针实际对齐等不变式；`Buffer` 基于 `ObjectRef`/`ObjectPtr` 实现共享所有权的不可变实现对象，对外暴露只读观察接口。
- 分配器抽象层（allocator.h + allocator.cpp）：`Allocator` 纯虚基类将 `AllocateStorage` 与公共入口 `TryAllocate` 分离，后者对返回的 `MemoryHandle` 做完整性校验（非空、非借用、设备匹配、对齐满足最小值），失败统一转为 `Status`；`AllocatorRegistry` 按 `DeviceType` 注册 `AllocatorProvider`，并按 `Device` 缓存单例 `Allocator`，`SetProvider` 会清空该类型的缓存实例。
- 具体实现：`cpu_allocator.{h,cpp}`、`cuda_allocator.{h,cpp}`、`cann_allocator.{h,cpp}` 分别提供各后端的具体 `Allocator` 与对应 Provider；`memory_junk_fill.{h,cpp}` 提供调试用内存填充工具，被上层测试或诊断使用。
依赖方向：具体分配器 → allocator 抽象 → buffer/memory_handle；registry 反向持有 provider 工厂，不感知具体后端。
