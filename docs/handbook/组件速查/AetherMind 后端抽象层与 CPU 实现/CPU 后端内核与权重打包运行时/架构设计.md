本模块以 `CpuBackend`（继承自 `Backend`）作为统一入口，将所有 CPU 算子子模块按 OpType 在 `KernelRegistry::Global()` 中静态注册；启动时由 `CpuBackendFactory` 调用 `DetectCpuCapabilities` 生成不可变的 `CpuCapabilities` 快照，`PrepareKernel` 根据该快照过滤候选内核并冻结成 `ResolvedKernel`。

- 权重路径：各算子子模块提供的 `*_internal.h` 定义参数构建器与形状校验，`cpu_packed_weight_layout.cpp` 提供 identity / BPanelF32Kc512Nr16 等 PackingRecipe，`packed_weight_validation.cpp` 校验逻辑 TensorView 是否满足行主连续与溢出约束，最终由 `PackWeights` 产出带 `selector_ + recipe_ + logical_shape` 的 `PackedWeight`。
- 运行期路径：`cpu_workspace_arena.cpp` 暴露全局工作区分配器，供 GEMM/Attention/RMSNorm 等微内核在推理阶段复用临时缓冲区。
- 能力路径：`cpu_capabilities.cpp` 检测 x86-64/AArch64 特性集，`cpu_info.cpp` 暴露给上层诊断；所有子内核（GEMM AVX2、RMSNorm AVX2 等）通过条件编译与 selector 匹配选择标量或向量化实现。

因此，子模块之间不直接互相调用，而是通过共享契约（`OpType`、`KernelSelector`、`PackingRecipe`、`KernelRegistry`、`CpuCapabilities`）解耦：算子只关心自身参数的构造与参考实现，编排职责集中在 `cpu_backend.cpp` 与 `cpu_backend_internal.h`。
