模块以 `basic_string.hpp` 为对外 API 入口，内部通过模板参数将存储布局与容量增长解耦：
- `BasicStringCore`（core.hpp）是核心骨架，负责构造/析构、拷贝/移动/赋值语义、空终止维护与分配协调；它不关心字节布局细节。
- `LayoutPolicy` 抽象层（layout_policy.hpp + generic_layout_policy.hpp + char_layout_policy.hpp）定义 `AmStringLayoutPolicy` / `AmStringDecodedLayoutPolicy` concept，默认 `GenericLayoutPolicy<CharT>` 使用 24 字节 Small/External 双态 union，按字符宽度选择元数据位宽并通过末字节探针编码 Small 状态；`char_layout_policy.hpp` 对 `char` 提供紧凑布局特化（借助 endianness）。
- `GrowthPolicy`（growth_policy.hpp）独立决定扩容公式（`kGrowthFactorDenominator=2`、`kLargeGrowthFactorDenominator=4`、`kMinHeapCapacity=32`、`kLargeThresholdBytes=4096`），由 `config.hpp` 集中暴露常量。
- `allocator_support.hpp` 封装 `AllocatorTraitsHelper`，统一处理 `propagate_on_copy_assignment` / `is_always_equal` 等分配器行为分支。
- `invariant.hpp`、`char_algorithms.hpp`、`utils/*` 提供断言与字符级操作。
- `string_fwd.hpp` 前置声明，`string.hpp` 仅导出 `amstring/u8string/u16string/u32string/wstring` 别名。
依赖方向单向：API → Core → Policy/Config/AllocatorSupport，Policy 之间互不依赖。
