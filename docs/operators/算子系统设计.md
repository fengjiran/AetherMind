# 算子系统设计

AetherMind 在模型准备期为 Prefill 和 Decode 构建执行计划，计划记录每一步调用哪个 kernel，请求绑定记录该 kernel 如何访问本次使用的张量，执行时再提供当前步骤的 workspace 和 KV 状态。

## 1. 从算子语义到执行

| 阶段 | 负责的模块 | 决策及其有效期 |
| --- | --- | --- |
| 定义语义与lowering graph | operators、graph、compiler | 算子定义端口、参数与输出规格，形状推导检查静态维度并为符号维度留下约束。编译器把语义图 lowering 为包含 kernel selector 的执行步骤描述。 |
| 构建执行计划 | execution、backend | `ExecutionPlanBuilder` 调用 `Backend::PrepareKernel`。CPU 后端按 selector、有效 CPU 特性和候选优先级选核。`ResolvedKernel` 携带函数指针、参数构建器、workspace 需求和预期的 packing recipe。执行层匹配 packed 产物、规划 workspace 偏移，由 `ExecutionStep` 持有冻结结果。 |
| 准备具体绑定 | execution、所选 kernel 的参数构建器 | `PrepareExecutionBindings` 拿到实际视图后验证形状与约束。需要参数的步骤各调用一次 `params_builder`，将指针、步长等稳定信息写入 `PreparedExecutionBindings` 持有的参数区。复用期间，视图的地址、dtype、形状和步长必须保持有效。 |
| 执行步骤 | execution、backend kernel | `LayerRunner` 取出已准备的参数，绑定本步的 workspace，并按需检查当前 KV 读写范围。例如写入前需确认本次追加的结束位置在缓存容量内。随后通过 `InvokePreparedKernel` 调用冻结入口，沿执行链传播 `Status`。 |

kernel 的统一入口为 `Status (*)(const KernelContext&) noexcept`。执行阶段复用已选 kernel 和已构造参数，准备完成后的 Decode 稳态零堆分配。请求准备和生成结果的存储有各自的分配时点。[计划构建](../../src/execution/execution_plan_builder.cpp) · [绑定期参数契约](../../include/aethermind/backend/kernel_types.h) · [步骤执行与 KV 检查](../../src/execution/layer_runner.cpp)

## 2. RMSNorm 实例：CPU FP32、plain 权重

### 语义与选核

`InferRmsNorm` 接受形如 `[..., H]` 的输入和形如 `[H]` 的权重，输出继承输入的形状和 dtype。每一行沿最后一维计算均方，加入有限且为正的 epsilon，取平方根的倒数，再逐元素乘以输入和权重。`H` 必须为正；前导维度可以为零。若权重长度和 `H` 都已知，推导时即可检查相等性；若无法静态证明相等，则留下维度相等约束，在具体绑定时验证。[语义推导](../../src/operators/ops/rmsnorm_op.cpp) · [RMSNorm 算子契约](rmsnorm/RMSNorm算子契约.md)

对于 FP32 输入、权重和输出，plain 路径注册了 reference 实现。构建包含 AVX2+FMA 实现，且有效 CPU 特性同时满足 AVX2 和 FMA 时，对应 descriptor 才有资格参与选核。缺少任一特性时，reference 仍可匹配该 selector。packed 权重有独立的 descriptor 和 recipe，其参数构建器通过 `packed_weight` 获取产物。[RMSNorm 注册与参数构建](../../src/backend/cpu/kernels/rmsnorm/rmsnorm_entry.cpp) · [冻结的 kernel 与 recipe](../../include/aethermind/backend/resolved_kernel.h)

### 绑定期的布局与别名检查

`BuildRmsNormF32Avx2FmaArgs` 从冻结的属性读取 epsilon，在本组视图上构造 `RmsNormA32W32KernelArgs`。以下检查决定内循环可采用哪些地址和指令。[实现](../../src/backend/cpu/kernels/rmsnorm/rmsnorm_entry.cpp)

- **行数与地址范围。** 使用带溢出检查的乘法将前导维度折叠成 `int64_t` 行数。零行成功返回，允许空 activation 视图的数据指针为 null。非空视图需满足指针、步长及可表示偏移的约束。
- **行距与列距。** 输入与输出使用各自的行步长，允许行尾 padding。对于形状 `[2, 3]`、步长 `[4, 1]` 的输入，第二行从元素偏移 4 开始。非空 AVX2 路径还要求输入、权重和输出的列步长均为 1；已选中该 kernel 后，绑定不满足此条件会返回 `InvalidArgument`。reference 可处理正的非单位列步长。
- **原地执行。** 输入与输出的地址、dtype、形状和步长完全一致时允许原地归一化。可写输出的各行须互不覆盖，输出与重复读取的权重须互不重叠。行内核保留 exact in-place 能力；若为独立缓冲区编写 `restrict` 特化，其入口须先证明读写范围不相交。

### 执行期的行循环

`RmsNormF32Avx2FmaEntry` 直接从 `ctx.kernel_params` 取出已验证参数，交给 `RunRmsNormF32Avx2Fma`。生产实现的行循环如下。[CPU FP32 行内核](../../src/backend/cpu/kernels/rmsnorm/rmsnorm_a32_w32_avx2.cpp)

```cpp
for (int64_t row = 0; row < args.row_count; ++row) {
    RmsNormF32RowAvx2Fma(args.output + row * args.output_row_stride,
                         args.input + row * args.input_row_stride,
                         args.weight,
                         args.hidden_size,
                         args.eps);
}
```

行内核先读完整行并完成平方和归约，再逐元素读取输入、乘以归一化因子和权重并写回，因此同一视图可安全用作输入和输出。向量宽度之外的尾部由标量循环处理。累加器数量、展开因子以及是否单独抽取微内核，都由具体实现和测量决定。

当前路径逐行串行执行。单请求 Decode 通常只有一行，按行切分只有一个任务。若为多行 Prefill 引入并行，应先明确线程池所有权、同步完成语义与串行阈值，再分别验证 Prefill 收益、单行 Decode 延迟、确定性、稳态分配和 TSAN 结果。[CPU 算子演进路线](cpu-operator-evolution.md)

## 3. 优化如何进入生产路径

以 RMSNorm 为例，变更按仓库的 O0–O4 工作流评审。工作包定义、基准比较方法和证据记录格式统一见[算子开发与优化工作流](../guides/operator-development-workflow.md)。

| 工作包 | RMSNorm 的验证内容 |
| --- | --- |
| O0 语义与合同 | 列明累加精度、数值容差、epsilon、零行、行列步长、地址溢出及别名规则。明确哪些输入是语义错误，哪些仅受具体 kernel 布局限制。 |
| O1 Reference | 保留独立、可审计的 reference；用它对照优化路径的数值结果。覆盖有尾部的 hidden size、带 padding 的行、exact in-place、非法重叠和缺少所需 ISA 时的 fallback。[已有 kernel 用例](../../tests/unit/backend/cpu/kernels/test_cpu_rmsnorm_kernel.cpp) |
| O2 性能基线 | 测量注册、选中且参数已准备的 kernel；绑定开销单独计时。分别报告 Decode 单行和 Prefill 多行。微内核数据用于定位瓶颈。[prepared 与绑定基准](../../tests/benchmark/cpu_kernels/benchmark_cpu_rmsnorm_kernel.cpp) |
| O3 方案与路线 | 为展开、布局或并行等非平凡改动写明目标 workload、瓶颈假设、备选方案和接受条件。 |
| O4 实验与决策 | 同机同配置交错比较基线和候选，记录 commit、命令、全部重复测量的原始数据与结论。提升生产优先级需有实际执行路径的验证；声称改善生成性能时补充端到端证据。[RMSNorm 基准记录](rmsnorm/benchmarks/desktop-54h5mmi-rmsnorm.md) |
