模块以「计划/绑定/上下文/调度/内核调用」五层划分：
- 计划层（execution_plan.h, state_alias_plan.h）：`ExecutionPlan` 持有已验证的 `ExecutionStep` 序列、逻辑值表、模型输入输出集合及 `StateAliasPlan`，通过静态工厂 `Create` 完成一致性校验并产出不可变计划。
- 绑定层（execution_bindings.h/.cpp）：两阶段准备——`PlanExecutionBindings` 计算激活区布局与外部只读依赖，`PrepareExecutionBindings` 分配激活存储并构建每步的 `StepTensorBinding` 与 `kernel_params`，由 `PreparedExecutionBindings` 通过 heap-stable storage 在移动后保持引用有效。
- 上下文层（execution_context.h/.cpp）：`ExecutionContext::Create` 校验 workspace 容量与 KV 几何，聚合 `PreparedExecutionBindings`、`WorkspaceArena*`、`KVCacheSessionView`，并提供 `BindWorkspace` 与 per-layer append 事务 scratch。
- 调度层（executor.h/.cpp + layer_runner.h/.cpp）：对外仅暴露 `Executor::Execute`；内部 `LayerRunner::Run` 顺序遍历步骤，对状态别名调用 `ValidateStateAliasesForStep`，再委托底层内核调用。
- 内核调用层（kernel_invoker.h/.cpp）：`InvokePreparedKernel` 消费已准备的 `kernel_params`，另提供 `BuildAndInvokeKernelForTesting` 测试辅助。

依赖方向单向向下：executor → layer_runner → kernel_invoker → backend/resolved_kernel；binding/plan/context 之间通过 `ExecutionPlanBindingKey` / `IsCompatible` 做冷路径兼容性检查，避免在执行热路径中持有任何编译器或图 IR 句柄。
