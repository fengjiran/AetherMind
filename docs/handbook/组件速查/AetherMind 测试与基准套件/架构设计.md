tests/ 作为纯测试容器，通过四层分工组织：
- unit/：按被测试子系统镜像源码目录，使用 GoogleTest 断言内核正确性。
- benchmark/：独立于 unit，使用 GoogleBenchmark；cpu_kernels/ 新增 `benchmark_cpu_kv16_execution.cpp`（KV16 Attention/KVUpdate 端到端执行路径）、`benchmark_cpu_kv16_kernels.cpp`（KV16 标量参考内核）与 `benchmark_cpu_projection_fusion.cpp`（A32/W16 投影内核 + PackWeights），模型基准 `models/model_benchmark.cpp` 新增 `--kv-dtype` / `--activation-dtype` CLI，输出 JSON schema_version=2 并记录 prefill/decode activation bytes。
- fixtures/：只读数据（HF 源模型、checksums.json、recipe.json、policy.json、kv16_reference/checksums.json），由 inference 与 final_validation 消费，版本化在仓库中随提交锁定。
- cmake/：自包含小 CMake 工程 + 脚本，验证对齐约束、spdlog/Python 依赖发现、CTest skip policy、标签分类等构建期契约。
四者共享同一份 aethermind 头文件与后端实现（由外部 build system 注入 include 路径），但各自拥有独立的 CMake target；fixtures 不参与编译仅以路径引用；cmake/*_project 子目录从上游重新拉取依赖证明接口契约稳定。
